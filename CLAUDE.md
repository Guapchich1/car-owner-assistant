# Помощник автовладельца

## О проекте
Веб-приложение для автовладельца:
- карточка машины по VIN (пользователь подтверждает характеристики);
- журнал работ и расходов;
- план ТО по регламенту модели и пробегу;
- ссылки на поиск запчастей и автосервисов;
- ИИ-помощник, который отвечает на вопросы со ссылками на источники.

Машины российского рынка. Код пишет ИИ-агент, команда проверяет.

## Стек
- Python 3.12, FastAPI, шаблоны Jinja2, HTMX, свои стили
  в app/static/style.css (по прототипу из docs/design/prototype/)
- SQLite + SQLAlchemy 2.0, миграции Alembic
- Настройки и ключи в .env
- pytest для тестов, ruff для проверки кода

## Структура
- app/main.py — запуск приложения
- app/routers/ — страницы
- app/db.py — подключение к БД (адрес — DATABASE_URL, по умолчанию
  sqlite:///./car_assistant.db)
- app/models.py — таблицы БД
- migrations/ — миграции Alembic (настройки — alembic.ini)
- app/services/ — логика (VIN, план ТО, LLM)
- app/templates/ — HTML-шаблоны
- app/data/ — справочники в JSON
- tests/ — тесты
- docs/ — документация

## Команды
Все команды — в PowerShell из папки проекта, с активированным окружением:
`.venv\Scripts\Activate.ps1`
- Установить библиотеки: `python -m pip install -r requirements.txt`
- Запустить приложение: `python -m uvicorn app.main:app --reload`
  — откроется по адресу http://127.0.0.1:8000, остановить: Ctrl+C
- Применить миграции (создать или обновить базу): `python -m alembic upgrade head`
- Создать новую миграцию после изменения app/models.py:
  `python -m alembic revision --autogenerate -m "Что изменилось"`
  — затем проверить созданный файл в migrations/versions/
- Пересобрать справочник моделей после изменения data/regulations_full.csv:
  `python scripts/build_catalog.py` — создаёт app/data/catalog.json (выборка,
  в git) и data/catalog_full.json (все модели, не в git)
- Запустить тесты: `python -m pytest`
- Проверить код: `python -m ruff check .`
- Те же проверки автоматически запускаются на GitHub при каждом PR.

## VIN
- Данные машины по VIN берём из apipoint.ru (метод vindecode), токен — в .env.
- До запроса проверяем формат VIN (17 символов, без I, O, Q) — запрос платный.
- Ответ сохраняем в базе с машиной, повторно не запрашиваем.
- Марку и модель из ответа сопоставляем со справочником моделей (app/data/).
- В справочнике популярные модели российского рынка с регламентом ТО;
  если модели в нём нет — используем общий регламент по умолчанию.
- Если apipoint недоступен или не нашёл VIN — пользователь выбирает модель
  из справочника вручную.
- Пользователь всегда подтверждает или исправляет данные.
- В тестах apipoint не вызываем, используем заглушку.

## ИИ-помощник
- Модель: YandexGPT Lite через библиотеку openai.
- Вся работа с LLM — только в app/services/llm.py.
- Ищем подходящие тексты в своей базе (SQLite FTS5), передаём их модели,
  ответ содержит ссылки на источники.
- В тестах настоящую LLM не вызываем, используем заглушку.

## Правила
- Перед «готово» запусти `python -m pytest` и `python -m ruff check .` — всё должно проходить.
- Новая функция — новый тест.
- Работай в ветке `feature/<имя>`, в main не коммить.
- Одна задача — одна ветка — один PR.
- Не трогай .env.
- Новые библиотеки и изменения структуры — только после согласования.
- Комментарии, интерфейс и коммиты — на русском.
- Если что-то неясно — спроси.
- Делай только то, что написано в задаче. Если видишь, что полезно сделать
  что-то ещё, — предложи и спроси, но без согласия не делай.
